# Content Structure – Steps

## Goal

Content is organised in folders, optional tabs inside a folder and Markdown pages, as described in
`content-structure.md`. Every folder, tab and page has a readable address under `/folders`, pages end in `.md`, and
items can be created and renamed and pages moved within their folder.

## Scope

- In:
  - the models `Folder` and `Tab`, and pages that live directly in a folder or in one of its tabs
  - one name rule for folders, tabs and pages, and name uniqueness per folder and per tab
  - addresses under `/folders` and actions in the query string (see "Addresses and actions" below)
  - creating and renaming folders, tabs and pages; creating and editing page content
  - moving a page within its folder
  - lists by name: folders, the pages of a folder, the pages of a tab and all pages of a folder
  - the content size limit, checked on create and edit only
  - a migration that places the existing pages in a folder `test-folder`
  - removing today's page delete, together with its button, action and tests
- Not in:
  - deleting and restoring folders, tabs or pages (soft delete, deleted item lists); until then nothing can be deleted
  - rights per folder, users and authentication
  - history and revert, concurrent changes and locking
  - links between pages, backlinks and broken links
  - search
  - moving a page to another folder, moving a tab to another folder
  - redirects from old addresses after a rename or move

## Addresses and actions

The rules every step follows:

- All content lives under the fixed prefix `/folders`. The rest of the root belongs to the app (`/api` today, later
  routes such as login or admin), so no folder, tab or page name is reserved.
- Addresses:
  - `/folders`: the list of folders
  - `/folders/<folder>`: a folder with its tabs and the pages placed directly in it
  - `/folders/<folder>/<tab>`: a tab with its pages
  - `/folders/<folder>/<page>.md`: a page placed directly in a folder
  - `/folders/<folder>/<tab>/<page>.md`: a page in a tab
- The `.md` belongs to the address, not to the name. A segment that ends in `.md` is a page, any other is a tab. Only
  the lowercase suffix counts: `/folders/<folder>/guides.MD` shows the not-found page.
- Actions are given in the query string as `?action=<action>`. Each route accepts only its own actions and opens the
  matching dialog or editor; an unknown action, or one that is not valid for the address, shows the not-found page.
  Closing a dialog returns to the address without the query string.
- Folders and tabs are created and renamed in dialogs. Pages are created and edited in the editor; they are renamed
  and moved in dialogs.
- Malformed names in an address are treated like missing items and show the not-found page, as today for slugs.
- Server Actions call `revalidatePath("/folders", "layout")`, which covers every address of the feature.

## Folders

### Goal

Folders exist: they can be created, listed and renamed, and each has its own address. Pages stay at `/pages` until the
next step.

### Build

- The shared name rule in `src/lib/names.ts`, with no server-only imports:
  - `NAME_PATTERN` `^[a-z0-9]+(-[a-z0-9]+)*$` and `NAME_MAX_LENGTH` 80, the rule of today's page slug
  - `nameSchema`: trimmed, required ("Name is required"), at most 80 characters, matching the pattern ("Use lowercase
    letters, digits and single hyphens")
  - `parseName(segment)`: the name if a URL segment is a valid name without surrounding whitespace, otherwise `null`
- Address helpers in `src/lib/addresses.ts`, pure functions used by routes, actions and links:
  - `folderPath(folder)`, `tabPath(folder, tab)`, `pagePath(folder, tab | null, page)`, each optionally with an action
  - `parsePageSegment(segment)`: the page name if the segment is a valid name followed by `.md`, otherwise `null`
  - `parseAction(searchParams, allowed)`: no action, an allowed action, or "invalid" for anything else
- `Folder` in `prisma/schema.prisma`: `id` (UUID, generated by PostgreSQL), `name` (unique), `createdAt`, `updatedAt`;
  a migration `add-folders`.
- Feature `src/features/folders/`:
  - `schema.ts`: `parseFolderId`, `folderInputSchema` and `parseFolderFormData` for the name
  - `queries.ts`: `listFolders()` by name, `getFolderByName(name)` wrapped in `cache()`
  - `actions.ts`: `createFolder` and `renameFolder` (id bound with `bind`), following the conventions in
    `architecture.md`; a unique violation on the folder name shows "Name is already in use" at the name field, detected
    like `isSlugTaken` in `src/features/pages/actions.ts`
  - `components/`: the folder list and a name dialog (Client Component) used for "New folder" and "Rename"
- Routes:
  - `/folders`: the folders by name with their last update, each linking to its folder; an empty state; a "New folder"
    button that links to `/folders?action=new`, which opens the dialog. Saving shows the new folder.
  - `/folders/<folder>`: the folder name as heading, an empty state for its content and a "Rename" button that links to
    `?action=rename`. Saving shows the folder at its new address; the old address shows the not-found page.
  - The browser title is built with `pageTitle()`.
- The app bar gets a "Folders" link next to the existing link to `/pages`.
- The name dialog focuses the name field when it opens and keeps the entered name after a rejected save.

### Test

- Unit tests:
  - `src/lib/names.test.ts`: valid names, empty, too long, uppercase, dots, double and leading or trailing hyphens,
    surrounding whitespace in `parseName`
  - `src/lib/addresses.test.ts`: the built paths, `parsePageSegment` with `.md`, `.MD`, `.md.md`, no suffix and an
    invalid name, and `parseAction` with no, allowed, unknown and repeated actions
  - `src/features/folders/schema.test.ts` and `actions.test.ts`: the database failure, taken name and missing folder
    branches with mocked `@/lib/db`
- End-to-end tests (`e2e/folders.spec.ts`), with a helper `createFolder()` in `e2e/support/`:
  - the empty state, and folders listed by name
  - creating a folder through the dialog, then seeing it
  - invalid and taken names show the error at the name field and keep the entered name
  - renaming a folder; the old address shows the not-found page
  - an unknown folder, a malformed folder name and an unknown action show the not-found page
  - cancelling a dialog returns to the address without the query string
- `e2e/hydration.spec.ts`: a case for the name dialog.

## Pages in folders

### Goal

Every page lives in a folder and is found at `/folders/<folder>/<page>.md`. The `/pages` routes and the page delete are
gone.

### Build

- `Page` in `prisma/schema.prisma`:
  - `folderId`: required, foreign key to `Folder` with `onDelete: Restrict`
  - `name`: the former `slug`, renamed; unique together with `folderId`
- Migration `pages-in-folders`: if any page exists, create the folder `test-folder` and place every page directly in
  it; rename `slug` to `name`; make `folderId` required; replace the unique index on `slug` by the one on
  `(folderId, name)`. Existing slugs are valid names, so they are kept.
- `src/features/pages/`:
  - `schema.ts`: the page form submits `content` only; the name has its own input for the save dialog of a new page and
    for the rename dialog, built on `nameSchema`. `RESERVED_SLUGS`, `slugSchema` and `parsePageSlug` are removed.
  - `derive.ts`: `deriveSlug` becomes `deriveName`, with the same rules.
  - `queries.ts`: `listFolderPages(folderId)` by name, without content; `getPage(folderName, pageName)` wrapped in
    `cache()`
  - `actions.ts`: `createPage(folderId)`, `updatePageContent(id)` and `renamePage(id)`; a taken name shows "Name is
    already in use". Renaming does not validate or touch the content, so the content limit never blocks it.
  - `deletePage`, `DeletePageButton` and their tests are removed.
- Routes:
  - `/` redirects to `/folders`; the app bar links only to `/folders`.
  - `/folders/<folder>`: the pages placed directly in the folder by name, with title and last update, each linking to
    its page; an empty state; a "New page" button linking to `?action=new`.
  - `/folders/<folder>?action=new`: the editor of today's `/pages/new`; the save dialog asks for the name, suggested
    with `deriveName`. "Cancel" returns to the folder. Saving shows the new page.
  - `/folders/<folder>/<page>.md`: the page view of today's `/pages/[slug]`, with "Edit" (`?action=edit`) and "Rename"
    (`?action=rename`) and no "Delete"; a breadcrumb with the folder and the page name with `.md`.
  - `?action=edit`: the edit form with the content only; saving shows the page.
  - `?action=rename`: the name dialog; saving shows the page at its new address.
  - `src/app/pages/` is removed.
- `prisma/seed.ts` creates a sample folder and places the sample pages in it, by fixed ids.
- `e2e/support/`: `createPage()` takes `folder` and creates a folder when none is given; it gets `name` instead of
  `slug`.

### Test

- Unit tests: the page schema without slug, `deriveName`, and the branches of `createPage`, `updatePageContent` and
  `renamePage` (taken name, missing page, database failure, malformed id).
- End-to-end tests: `create-page.spec.ts`, `edit-delete-page.spec.ts` (renamed to `edit-page.spec.ts`) and
  `pages.spec.ts` move to the new addresses, and the delete tests are removed. New cases:
  - `/` shows the folder list
  - the pages of a folder are listed by name; the empty state
  - renaming a page; the old address shows the not-found page
  - renaming a page whose content is above the content limit (stored directly in the test database) succeeds
  - the same page name in two folders
  - not-found for `/folders/<folder>/<page>` without `.md`, for `.MD`, for a page of another folder, for an unknown
    action and for `/pages`
- `e2e/hydration.spec.ts`: the existing cases at their new addresses.

## Tabs

### Goal

A folder can have tabs. A page lives either directly in its folder or in one of its tabs, with names unique where they
meet.

### Build

- `Tab` in `prisma/schema.prisma`: `id`, `folderId` (foreign key to `Folder`, `onDelete: Restrict`), `name`,
  `createdAt`, `updatedAt`; `name` unique together with `folderId`; `(id, folderId)` unique as the target of the page's
  foreign key.
- `Page.tabId`: optional. A composite foreign key `(tabId, folderId)` to `Tab(id, folderId)` makes sure a page's tab
  belongs to the page's folder.
- Page name uniqueness, in the database:
  - unique `(tabId, name)` for pages in a tab
  - unique `(folderId, name)` only for pages with no tab: a partial unique index with Prisma's `partialIndexes` preview
    feature (available in the installed Prisma; follow its documentation for the `where` syntax). It replaces the
    unique index of the previous step.
  - tab names and page names are checked separately, so a tab `guides` and a page `guides.md` placed directly in the
    folder can exist side by side.
- Migration `add-tabs`.
- Tabs are part of `src/features/folders/`: `listTabs(folderId)` by name, `getTab(folderName, tabName)`, `createTab`
  and `renameTab` with "Name is already in use" for a taken tab name.
- Routes:
  - `/folders/<folder>`: a navigation bar above the content – the folder itself first, then its tabs by name, each a
    link; a "New tab" button linking to `?action=new-tab`, which opens the name dialog. Saving shows the new tab.
  - `/folders/<folder>/<tab>`: the same navigation bar with the tab selected; the tab's pages by name with title and
    last update; an empty state; "New page" (`?action=new`) and "Rename" (`?action=rename`).
  - `/folders/<folder>/<tab>?action=new`: the editor; the new page is placed in the tab. "Cancel" returns to the tab.
  - `/folders/<folder>/<tab>/<page>.md`: the page view with edit and rename as for pages placed directly in a folder;
    the breadcrumb shows folder, tab and page.
  - A page created without a tab is placed directly in the folder.
- `e2e/support/`: `createTab()`; `createPage()` takes an optional `tab`.

### Test

- Unit tests: the tab schema and the branches of `createTab` and `renameTab`; `createPage` with a tab.
- End-to-end tests (`e2e/tabs.spec.ts`):
  - creating a tab through the dialog; invalid and taken names; renaming a tab and the old address showing not-found
  - the same tab name in two folders
  - the navigation bar lists the folder and its tabs by name
  - creating a page in a tab, viewing, editing and renaming it
  - `overview.md` placed directly in a folder and in two of its tabs at the same time; a taken name in the same tab
  - a tab `guides` and a page `guides.md` in the same folder, each at its own address
  - not-found for an unknown tab, for a page in the wrong tab, for an unknown action on a tab and for `?action=new-tab`
    on a tab address
- `e2e/hydration.spec.ts`: the name dialog on a tab.

## Moving pages

### Goal

A page can be moved within its folder: from the folder into a tab, from a tab back to the folder, or to another tab.

### Build

- `movePage(id)` in `src/features/pages/actions.ts`: the target is the folder itself or one of its tabs, given by tab
  id or none. A tab of another folder is refused by the composite foreign key and reported as an error. A taken name at
  the target shows "A page with this name already exists there". The content is not validated, so the content limit
  never blocks a move.
- `?action=move` on a page address opens a "Move page" dialog with a choice of the folder itself and its tabs by name;
  the current place is preselected. Saving shows the page at its new address.

### Test

- Unit tests: the branches of `movePage` (taken name, missing page, missing or foreign tab, database failure, malformed
  ids).
- End-to-end tests (`e2e/move-page.spec.ts`):
  - folder to tab, tab to folder and tab to tab; the page shows at its new address and the old address shows not-found
  - a taken name at the target shows the error and the page stays where it was
  - moving a page whose content is above the content limit succeeds
- `e2e/hydration.spec.ts`: the move dialog.

## All pages of a folder

### Goal

A folder can list all its pages at once, each with its tab.

### Build

- `listAllFolderPages(folderId)`: all pages of the folder without content, by name and then by tab, pages placed
  directly in the folder first.
- `/folders/<folder>?view=all`: the list with name, tab, title and last update, each page linking to its address; an
  empty state. The navigation bar gets an "All pages" entry after the tabs.
- `view` is checked like `action`: an unknown value shows the not-found page.

### Test

- End-to-end tests:
  - the list shows pages placed directly in the folder and in its tabs, in the specified order, each with its tab
  - the empty state
  - an unknown `view` shows the not-found page
