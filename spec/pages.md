# HippoWiki – Pages

The wiki page feature as built. Code: `src/features/pages/`, routes under `src/app/folders/`. Where pages live –
folders, tabs, names and addresses – is described in `content-structure.md`.

## Model

`Page` in `prisma/schema.prisma`:

- `id`: UUID, primary key, generated by PostgreSQL
- `title`: text, derived from the content's title heading on every save (see below) and never entered directly; kept
  as a column for the page lists and the browser tab. A page stored before titles were derived keeps its stored title
  until its next save.
- `name`: text, the page's part of its address, followed by `.md`; its rule and uniqueness are in
  `content-structure.md`
- `content`: text, the Markdown source
- `folderId`, `tabId`: the folder the page lives in and, if it has one, its tab (see `content-structure.md`)
- `createdAt`, `updatedAt`: timestamps
- `deletedAt`: `null` for a page that is not deleted, the time of deletion otherwise (see `page-deletion.md`)

## Input rules

Defined in `src/features/pages/schema.ts`, with the length limits in `src/features/pages/limits.ts`. The forms are
read by `src/features/pages/forms.ts`; `src/features/pages/service.ts` validates the same input again before it
writes:

- Each form submits only what it changes:
  - a new page: `name`, `content` and the place, a tab or the folder itself
  - editing: `content` only
  - moving or renaming: `name` and the place, a tab or the folder itself
  - deleting: nothing; restoring: `name` and the place (see `page-deletion.md`)
- The place is submitted in the field `place`: the id of a tab of the folder, or empty for the folder itself. A
  malformed tab id shows "This tab no longer exists.", together with the field errors, if there are any; a tab that no
  longer exists or belongs to another folder shows the same message.
- The title is derived from the content by the schemas for creating and editing a page; a submitted `title` field is
  ignored. Titles need not be unique.
- `name` follows the name rule in `content-structure.md`. A name that is taken where the page lives shows "Name is
  already in use"; no suffix is added automatically.
- `content` is at most 100,000 characters and must start with a title heading. Content without a title is refused with
  "Content must start with a title heading: # Title" at the content field. Line breaks are stored as LF.
- The content is validated when a page is created or edited. Moving or renaming neither validates nor touches it.
- Validation errors are shown at the form fields; the entered values are kept.

## Derived title and name

Defined in `src/features/pages/derive.ts` (`titleFromContent`, `deriveName`), shared by server and client code:

- The title heading: after optional blank lines, the content must start with a level-one ATX heading – `#`, then a
  space or tab, then the text. Up to three leading spaces and an optional closing `#` sequence are allowed, as in
  CommonMark. Nothing else counts: not a setext heading (`Title` underlined with `===`), not a `##` heading, and not a
  heading after any text, list, quote, code block, HTML or link reference definition.
- The title text: the content is parsed as GitHub Flavored Markdown, as the page view renders it, and the heading is
  reduced to plain text. Emphasis, strikethrough, code spans and links keep only their text, images their alt text,
  and raw HTML stays as typed text. Runs of whitespace become a single space, the text is trimmed and cut to 200
  characters without splitting a surrogate pair.
- There is no title, and the content is refused, when there is no title heading or its text has no letter or digit in
  any script, such as `#`, `# **` or `# ...`. There is no fallback title.
- The title is derived again on every save, so changing the heading changes the title.
- The suggested name is derived from the title: ä/ö/ü/ß become ae/oe/ue/ss, other accents are dropped, everything
  except `a-z0-9` becomes a single `-`, and a name longer than 80 characters is cut at a word boundary. A title in a
  non-Latin script gives an empty name.
- The name is suggested only in the save dialog of a new page. The name never changes automatically, even when the
  heading changes.
- The seed and the end-to-end helper `createPage()` derive the title from the content as well.

## Routes

A page has the address `/folders/<folder>/<page>.md` or, in a tab, `/folders/<folder>/<tab>/<page>.md`. Both show the
same views; actions are given as `?action=<action>` (see `content-structure.md`).

- New page – `?action=new` on a folder or tab address: content first – a monospace Markdown textarea with "Save" and
  "Cancel" (back to the folder or tab). "Save" checks the content on the client with `titleFromContent`; without a
  title it shows the error at the content field and does not open the dialog. Otherwise it opens the "Save page"
  dialog, which asks for the name and the place (see `content-structure.md`). The name is prefilled from the title
  derived from the content each time the dialog opens and focused once it has opened; below the name it shows the
  address the page will get at the chosen place. The title is not shown and not submitted. Errors from the server are
  shown in the open dialog and keep name, place and content; "Cancel" in the dialog closes it and keeps the content.
  Saving shows the new page.
- The page address: the folder breadcrumb (see `content-structure.md`) with the folder list, the folder, the tab if
  the page has one, and the page name with `.md`. Below it the last update and "Edit", "Move or rename" and "Delete"
  above a divider, then the rendered Markdown (GitHub Flavored Markdown, raw HTML shown as text, unsafe link URLs removed). Markdown
  images are shown only from the wiki itself: the Content Security Policy (`img-src 'self' data:`, see
  `architecture.md`) makes the browser block an image of another host, and react-markdown removes a `data:` URL. The
  stored title is not shown; the content's `#` heading is the page's only level-one heading. Markdown headings are
  drawn two Typography sizes smaller than their tag (`h1` as `h3`, which is the size page titles had). The browser tab
  uses the stored title.
- `?action=edit`: the page form with the content only, prefilled; there is no title or name field. The form opens with
  the cursor at the start of the content. Saving derives the title again and shows the page; content without a title
  or above the limit shows the error at the content field, keeps the entered content and focuses the field.
- `?action=move-or-rename`: the "Move or rename page" dialog on top of the page (see `content-structure.md`). Saving
  stores name and place together and shows the page at its new address.
- `?action=delete`: the "Delete page" dialog on top of the page (see `page-deletion.md`). Deleting leads to the folder
  or tab the page was in.
- Saving a page that no longer exists or is deleted shows an error message and leaves the focus where it is.
- `GET /api/health`: `{ "status": "ok" }` while the database is reachable, status 503 and a logged error otherwise.

## Current limits

- no rights and no author: everyone who is logged in can read and change every page (see `users-and-login.md`)
- a deleted page cannot be removed for good and is restored only into its own folder (see `page-deletion.md`)
- no search, no `[[wiki links]]`, no history, no attachments
- raw Markdown editing in a textarea
- the title comes only from a leading `# Title` heading: no setext headings, no front matter, no live display of the
  derived title while editing an existing page
- no redirects from the previous address after a page is renamed or moved
- Markdown images only from the wiki itself: the browser blocks images of other hosts without a message in the page,
  and `data:` images have their address removed
