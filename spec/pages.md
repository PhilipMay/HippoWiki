# HippoWiki – Pages

The wiki page feature as built in the prototype. Code: `src/features/pages/`, routes under `src/app/pages/`.

## Model

`Page` in `prisma/schema.prisma`:

- `id`: UUID, primary key, generated by PostgreSQL
- `title`: text, derived from the content's title heading on every save (see below) and never entered directly; kept
  as a column for the page list, the browser tab and the delete dialog. A page stored before titles were derived keeps
  its stored title until its next save.
- `slug`: text, unique, the last part of the page's address `/pages/<slug>`
- `content`: text, the Markdown source
- `createdAt`, `updatedAt`: timestamps

## Input rules

Defined in `src/features/pages/schema.ts`, with the length limits in `src/features/pages/limits.ts`:

- The forms submit `slug` and `content` only. The title is derived from the content in the create and update actions;
  a submitted `title` field is ignored. Titles need not be unique.
- `slug` is trimmed, required, at most 80 characters and matches `^[a-z0-9]+(-[a-z0-9]+)*$` (lowercase letters and
  digits in groups joined by single hyphens). `new` is reserved, because `/pages/new` is a route. A slug that another
  page uses shows "Slug is already in use"; no suffix is added automatically.
- `content` is at most 100,000 characters and must start with a title heading. Content without a title is refused with
  "Content must start with a title heading: # Title" at the content field. Line breaks are stored as LF.
- Validation errors are shown at the form fields; the entered values are kept.

## Derived title and slug

Defined in `src/features/pages/derive.ts` (`titleFromContent`, `deriveSlug`), shared by server and client code:

- The title heading: after optional blank lines, the content must start with a level-one ATX heading – `#`, then a
  space or tab, then the text. Up to three leading spaces and an optional closing `#` sequence are allowed, as in
  CommonMark. Nothing else counts: not a setext heading (`Title` underlined with `===`), not a `##` heading, and not a
  heading after any text, list, quote, code block, HTML or link reference definition.
- The title text: the content is parsed as GitHub Flavored Markdown, as the page view renders it, and the heading is
  reduced to plain text. Emphasis, strikethrough, code spans and links keep only their text, images their alt text,
  and raw HTML stays as typed text. Runs of whitespace become a single space, the text is trimmed and cut to 200
  characters without splitting a surrogate pair.
- There is no title, and the content is refused, when there is no title heading or its text has no letter or digit in
  any script, such as `#`, `# **` or `# ...`. There is no fallback title.
- The title is derived again on every save, so changing the heading changes the title.
- The suggested slug is derived from the title: ä/ö/ü/ß become ae/oe/ue/ss, other accents are dropped, everything
  except `a-z0-9` becomes a single `-`, and a slug longer than 80 characters is cut at a word boundary. A title in a
  non-Latin script gives an empty slug.
- The slug is suggested only in the save dialog of a new page. The slug never changes automatically, even when the
  heading changes.
- The seed and the end-to-end helper `createPage()` derive the title from the content as well.

## Routes

- `/` redirects to `/pages`; the app bar links to `/pages`.
- `/pages`: all pages with title and last update, most recently updated first, each linking to its page; an empty state
  when there are no pages; a "New page" button.
- `/pages/new`: content first – a monospace Markdown textarea with "Save" and "Cancel" (back to `/pages`). "Save" checks
  the content on the client with `titleFromContent`; without a title it shows the error at the content field and does
  not open the dialog. Otherwise it opens the "Save page" dialog, which shows the derived title read-only (not
  submitted) and asks for the slug, prefilled from the title each time the dialog opens and focused once it has
  opened. Errors from the server are shown in the open dialog; "Cancel" in the dialog closes it and keeps the content.
  Saving shows the new page.
- `/pages/[slug]`: last update, "Edit" and "Delete" above a divider, then the rendered Markdown (GitHub Flavored
  Markdown, raw HTML shown as text, unsafe link URLs removed). The stored title is not shown; the content's `#`
  heading is the page's only level-one heading. Markdown headings are drawn two Typography sizes smaller than their tag
  (`h1` as `h3`, which is the size page titles had). The browser tab uses the stored title. "Edit" opens the edit form;
  "Delete" asks for confirmation in a dialog that names the page by its stored title, then deletes it and returns to
  the list.
- `/pages/[slug]/edit`: the page form with slug and content, prefilled; there is no title field. Saving derives the
  title again and shows the page at its possibly new address; content without a title shows the error at the content
  field and keeps all entered values. Editing a page that was deleted in the meantime shows an error message.
- Unknown or malformed slugs, old UUID addresses and the previous slug of a renamed page show the not-found page.
- `GET /api/health`: `{ "status": "ok" }` while the database is reachable, status 503 and a logged error otherwise.

## Current limits

- one user, no login
- no search, no `[[wiki links]]`, no history, no attachments
- raw Markdown editing in a textarea
- the title comes only from a leading `# Title` heading: no setext headings, no front matter, no live display of the
  derived title while editing an existing page
- no redirects from a previous slug after a page is renamed
