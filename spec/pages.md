# HippoWiki – Pages

The wiki page feature as built in the prototype. Code: `src/features/pages/`, routes under `src/app/pages/`.

## Model

`Page` in `prisma/schema.prisma`:

- `id`: UUID, primary key, generated by PostgreSQL
- `title`: text
- `slug`: text, unique, the last part of the page's address `/pages/<slug>`
- `content`: text, the Markdown source
- `createdAt`, `updatedAt`: timestamps

## Input rules

Defined in `src/features/pages/schema.ts`:

- `title` is trimmed, required and at most 200 characters. Titles need not be unique.
- `slug` is trimmed, required, at most 80 characters and matches `^[a-z0-9]+(-[a-z0-9]+)*$` (lowercase letters and
  digits in groups joined by single hyphens). `new` is reserved, because `/pages/new` is a route. A slug that another
  page uses shows "Slug is already in use"; no suffix is added automatically.
- `content` may be empty and is at most 100,000 characters. Line breaks are stored as LF.
- Validation errors are shown at the form fields; the entered values are kept.

## Derived title and slug

Defined in `src/features/pages/derive.ts`, used when a new page is saved:

- The suggested title is the text of the first ATX heading (`#` to `######`) of the content, skipping fenced code
  blocks; a closing `#` sequence is removed and the text is cut to 200 characters. Without a heading it is empty.
  Inline Markdown is kept as typed; setext headings are not recognised.
- The suggested slug is derived from the title: ä/ö/ü/ß become ae/oe/ue/ss, other accents are dropped, everything
  except `a-z0-9` becomes a single `-`, and a slug longer than 80 characters is cut at a word boundary. A title in a
  non-Latin script gives an empty slug.
- In the save dialog the slug follows the title until the user edits the slug. The edit page never changes the slug
  automatically.

## Routes

- `/` redirects to `/pages`; the app bar links to `/pages`.
- `/pages`: all pages with title and last update, most recently updated first, each linking to its page; an empty state
  when there are no pages; a "New page" button.
- `/pages/new`: content first – a monospace Markdown textarea with "Save" and "Cancel" (back to `/pages`). "Save" opens
  the "Save page" dialog with "Title" and "Slug", prefilled each time it opens from the content (see above). Errors are
  shown in the open dialog; "Cancel" in the dialog closes it and keeps the content. Saving shows the new page.
- `/pages/[slug]`: title, last update and the rendered Markdown (GitHub Flavored Markdown, raw HTML shown as text,
  unsafe link URLs removed). "Edit" opens the edit form; "Delete" asks for confirmation in a dialog that names the
  page, then deletes it and returns to the list.
- `/pages/[slug]/edit`: the page form with title, slug and content, prefilled. Saving shows the page at its possibly
  new address. Editing a page that was deleted in the meantime shows an error message.
- Unknown or malformed slugs, old UUID addresses and the previous slug of a renamed page show the not-found page.
- `GET /api/health`: `{ "status": "ok" }` while the database is reachable, status 503 and a logged error otherwise.

## Current limits

- one user, no login
- no search, no `[[wiki links]]`, no history, no attachments
- raw Markdown editing in a textarea
- no redirects from a previous slug after a page is renamed
