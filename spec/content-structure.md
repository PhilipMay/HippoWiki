# HippoWiki – Content Structure

The content structure as built: folders, optional tabs inside a folder and Markdown pages. Code: `src/features/folders/`
(folders and tabs), `src/features/pages/` (pages), `src/lib/names.ts`, `src/lib/addresses.ts` and the routes under
`src/app/folders/`. What a page itself is – its content, derived title, editor and rendering – is described in
`pages.md`.

## Overview

Content has three levels:

- **Folder**: the top level. A folder groups related content, such as one project, team or topic. Folders are also the
  unit that access rights will later be attached to.
- **Tab**: an optional section inside a folder, such as "guides", "meetings" or "archive".
- **Page**: a Markdown document. A page lives either directly in a folder or in one tab of that folder, and so always in
  exactly one folder.

There is no deeper nesting: no folders inside folders and no tabs inside tabs. A new folder has no tabs; a folder may
hold pages directly and have tabs at the same time.

## Models

In `prisma/schema.prisma`:

- `Folder`: `id` (UUID, generated by PostgreSQL), `name` (unique), `createdAt`, `updatedAt`
- `Tab`: `id`, `folderId`, `name`, `createdAt`, `updatedAt`
  - `name` is unique together with `folderId`.
  - `(id, folderId)` is unique as the target of the page's foreign key.
- `Page`, as far as the structure goes (the other fields are in `pages.md`):
  - `folderId`: required
  - `tabId`: optional; without a tab the page is placed directly in its folder
  - A composite foreign key `(tabId, folderId)` to `Tab(id, folderId)` makes sure a page's tab belongs to the page's
    folder.
- All foreign keys use `onDelete: Restrict`.
- The migration `pages_in_folders` puts pages without a folder directly into a folder `test-folder`, which it creates
  if there is any such page.

## Names

Defined in `src/lib/names.ts`, shared by server and client code:

- Folders, tabs and pages each have a name, which is also their part of the address.
- A name is trimmed, required ("Name is required"), at most 80 characters and matches `^[a-z0-9]+(-[a-z0-9]+)*$`
  (lowercase letters and digits in groups joined by single hyphens; "Use lowercase letters, digits and single hyphens").
  A name never contains a dot.
- No name is reserved: all content lives under `/folders`, and actions are in the query string.
- Names are unique only where they meet, each enforced by a unique index in the database:
  - folder names across the wiki
  - tab names within their folder
  - page names within their tab
  - the names of pages placed directly in a folder among those pages only: a partial unique index on
    `(folderId, name)` for pages without a tab
  - Tab names and the names of pages placed directly in the folder are separate: a tab `guides` and a page `guides`
    placed directly in the same folder exist side by side, because `.md` keeps their addresses apart.
- A taken name shows "Name is already in use" at the name field; no suffix is added automatically.
- A name never changes automatically. The page title is separate from the name (see `pages.md`).

## Addresses

Built and parsed in `src/lib/addresses.ts`:

- All content lives under the fixed prefix `/folders`. The rest of the root belongs to the app (`/api` today).
- The addresses:
  - `/folders`: the list of folders
  - `/folders/<folder>`: a folder
  - `/folders/<folder>/<tab>`: a tab
  - `/folders/<folder>/<page>.md`: a page placed directly in a folder
  - `/folders/<folder>/<tab>/<page>.md`: a page in a tab
- The `.md` belongs to the address, not to the name. A segment that ends in `.md` is a page, any other is a tab. Only
  the lowercase suffix counts: `/folders/<folder>/guides.MD` shows the not-found page.
- Malformed names in an address are treated like missing items and show the not-found page, as do an unknown folder,
  tab or page and a page of another folder or tab. Pages have no address outside `/folders`; `/pages` shows the
  not-found page.
- A rename or move changes the address. There are no redirects from the old address; it shows the not-found page.

## Actions and views

- An action is given in the query string as `?action=<action>` and opens a dialog or the editor:

  | Address    | Action    | Opens                                                   |
  | ---------- | --------- | ------------------------------------------------------- |
  | `/folders` | `new`     | the "New folder" dialog                                 |
  | folder     | `new`     | the editor for a new page placed directly in the folder |
  | folder     | `rename`  | the "Rename folder" dialog                              |
  | folder     | `new-tab` | the "New tab" dialog                                    |
  | tab        | `new`     | the editor for a new page in the tab                    |
  | tab        | `rename`  | the "Rename tab" dialog                                 |
  | page       | `edit`    | the edit form (see `pages.md`)                          |
  | page       | `rename`  | the "Rename page" dialog                                |
  | page       | `move`    | the "Move page" dialog                                  |

- A folder address also has the view `?view=all`, the list of all its pages.
- Each address accepts only its own actions and views. An unknown, empty or repeated action or view, one of another
  address, and a view together with an action show the not-found page.
- A dialog is shown on top of the content of its address. Saving leads to the item's address, cancelling and the
  Escape key to the address without the query string.
- Folders and tabs are created and renamed in the name dialog. Pages are created and edited in the editor; they are
  renamed in the name dialog and moved in the "Move page" dialog.
- The name dialog focuses the name field when it opens and keeps the entered name after a rejected save.

## Routes

- `/` redirects to `/folders`; the app bar links to `/folders`.
- `/folders`: the folders with their last update, each linking to its folder; an empty state when there are none; a
  "New folder" button.
- `/folders/<folder>`: the folder name as heading with "Rename" and "New page", the navigation bar, and the pages
  placed directly in the folder; an empty state when there are none.
- `/folders/<folder>?view=all`: the same heading and navigation bar, and all pages of the folder in a table with name,
  tab, title and last update, each name linking to its page; an empty state when the folder has no pages at all.
- `/folders/<folder>/<tab>`: the folder name as heading, the navigation bar with the tab selected, the tab name with
  "Rename" and "New page", and the pages of the tab; an empty state when there are none.
- The navigation bar of a folder: the folder itself first, then its tabs, then "All pages", each a link, with the
  current entry marked; and a "New tab" button.
- Page addresses are described in `pages.md`.
- Browser titles are built with `pageTitle()`: "Folders", the folder name, `<tab> – <folder>` and
  `All pages – <folder>`.

## Changing the structure

Server Actions in `src/features/folders/actions.ts` (`createFolder`, `renameFolder`, `createTab`, `renameTab`) and
`src/features/pages/actions.ts` (`createPage`, `updatePageContent`, `renamePage`, `movePage`):

- Folders, tabs and pages can be created and renamed.
- A page created on a folder address is placed directly in the folder, one created on a tab address in that tab.
- A page can be moved within its folder: from the folder into one of its tabs, from a tab back to the folder, or to
  another tab. The dialog offers the folder itself and its tabs, with the current place preselected.
  - A page of the same name at the target shows "A page with this name already exists there"; the page stays where it
    was.
  - A tab of another folder is refused by the composite foreign key and reported like a tab that no longer exists.
- Renaming and moving do not validate or touch the content.
- A folder, tab or page that no longer exists when its form is saved shows a message above the form.
- Every action redirects to the stored address of the item, never to one built from submitted values, and calls
  `revalidatePath("/folders", "layout")`, which covers every address of the feature.

## Lists and order

- Folders, tabs and pages are listed by name, in the order of the database's collation.
- The page lists of a folder and of a tab show title, name with `.md` and last update.
- The list of all pages of a folder is ordered by name and then by tab; among pages of the same name, the one placed
  directly in the folder comes first.
- Lists show names and metadata only, never page content.

## Limits

- Names are at most 80 characters long.
- The content limit of a page (see `pages.md`) is checked when a page is created or edited. Renaming and moving do not
  check it, so a limit lowered later never blocks them.

## Current limits

- Nothing can be deleted or restored: no folder, tab or page.
- No rights per folder; one user, no login.
- A page cannot be moved to another folder, a tab cannot be moved to another folder.
- No redirects from old addresses after a rename or move.
- No history, no handling of concurrent changes, no links between pages, no search.
